# Антон — тестовый пилот

Интерактивный прототип планового распределения фиктивных заявок между вымышленными амбулаториями и стационарами Челябинской области.

> Пилот работает только с тестовыми данными. Не вводите реальные ФИО, номера полиса/СНИЛС, диагнозы, комментарии и документы. В форме доступны только фиктивные образцы файлов. Это не медицинская система и не защищённый контур.

## Что можно пройти

- **Врач амбулатории:** создать черновик или опубликованную заявку; редактировать только созданные своим аккаунтом записи; отвечать на запрос уточнения.
- **Врач стационара:** видеть опубликованные заявки из общего тестового реестра; фильтровать по статусу, диагнозу, кодам, очному осмотру и параметрам; запросить уточнение, отказать с причиной, предложить дату и условия.
- **Маршрут:** записать контакт, выбор пациента, подтверждение даты, прибытие, госпитализацию и итог либо вернуть заявку в подбор. Связь с пациентом и реальные уведомления не выполняются.
- **Пациент:** ввести уникальный тестовый код и увидеть статус, приглашение и следующую инструкцию только для одной связанной фиктивной заявки.
- **Администратор:** создавать и блокировать тестовые аккаунты, просматривать фиктивные заявки и локальную историю, сбрасывать демо.

Сверку с каждым Use Case см. в [UC_CHECKLIST.md](UC_CHECKLIST.md).

## Начальные тестовые учётные данные

- Врач стационара: `inpatient1` / `DEMO-1234`
- Врач амбулатории № 1: `amb-1` / `DEMO-1234`
- Врач амбулатории № 2: `amb-2` / `DEMO-1234`
- Врач амбулатории № 3: `amb-3` / `DEMO-1234`
- Пациент: код `TEST-1042`
- Администратор: `admin` / `DEMO-1234`

Вход врачей выполняется логином и паролем, пациента — только демо-кодом. Учётные данные встроены в открытый код и предназначены исключительно для демонстрации.

## База данных

Пилот сохраняет фиктивные аккаунты, заявки и действия в браузерной **IndexedDB** (`anton-synthetic-pilot`). Данные остаются в том же профиле браузера после перезагрузки. Они не передаются другим пользователям и не синхронизируются между устройствами. Сброс демо доступен администратору.

В [database/pilot-schema.sql](database/pilot-schema.sql) лежит проект реляционной схемы PostgreSQL для отдельного API-пилота с тестовыми данными. Текущий сайт к PostgreSQL не подключается. Серверная версия должна обращаться к БД только через API; подключать браузер напрямую нельзя. Детали — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Запуск

Требуется Node.js 18 или новее. Зависимостей npm нет.

```sh
npm start
```

Откройте http://127.0.0.1:4173. Статические файлы сайта находятся в `dist/`.

```sh
npm run check
```

Проверка валидирует синтаксис скриптов, наличие ресурсов и ключевых частей всех UC. Локальная демонстрация использует только вымышленные записи.

## Ограничения пилота

IndexedDB и проверка ролей в JavaScript нужны для демонстрации сценариев и не являются защитой доступа: пользователь может изменить данные браузера. Нет общей серверной БД, настоящей аутентификации, сообщений пациентам, загрузки пользовательских файлов, реальных справочников и рабочих мест. Публичная GitHub Pages подходит только для показа вымышленных данных.
